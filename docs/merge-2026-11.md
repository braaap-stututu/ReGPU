# The November 2026 merge: what came in, and what was decided

On 20 Nov 2026, braaap-stututu/ReGPU `main` went from `7320e6a` to `182afe2`, 214 commits. This file records where the
code came from and why each conflict was resolved the way it was. Use it before re-porting anything from these sources.

## Where two versions of one feature met

- **Occlusion queries with draw workers:** the stack's tile-span design (`regpu-worker-queries`, `zpd-tile-spans`,
  `draw-thread-pieces`). PGR4's logged queries (`99403c0`) are reverted in `383bf1d`; they would split tile spans
  across worker pieces.
- **Texture budget:** the stack's (`less-ram`, `cache-release`, `texture-budget-cached`). Main's `73b05f9` and
  `7a2c6b6` were dropped.
- **FSR:** the stack's `fsr3.cpp` (one context per setup, Prepare/Dispatch on the replay thread, FSR 4 where offered,
  XeSS). Kept from main:
  - the reactive mask and the exception guards;
  - `Fsr4Evaluate` and camera cuts;
  - `REGPU_VIEW_*`;
  - temporal upscalers only on frames with a 3D scene, and MSAA 1x under them.
- **Lean fetches:** skipped when a fetch uses setTexLOD or a register LOD (main's `22b9586`).
- **Fences:**
  - `REGPU_EARLY_FENCES_SKIP_WRITEBACKS` combined with `REGPU_TRUTHFUL_FENCES`.
  - The interrupt drain keeps `REGPU_NO_INTERRUPT_DRAIN` and uses `NoFenceOrder()`.
- **regpu::SetMsaa:** blit pipelines per sample count. `ApplyOutputSize`, `ApplyFrameSize` and `ApplyMsaa` share
  `WaitGpuIdle` and `DropSurfaces`.
- **Presenter:**
  - `REGPU_ADAPTER`, else `PickAdapter` (the high-performance GPU).
  - Main's child-window fullscreen with the stack's monitor row (`REGPU_TRIPLE`).
  - The host presenter (dwreckgg) runs the frame end synchronously; `REGPU_ASYNC_PRESENT` stands down for it.
- **Resolve bands (FH1) and the stack's enclosing resolves:** both kept. The band row is a blit origin
  (`srcOrigin.y = -destRow`). A band skips `ResolveIntoEnclosing`. **FM3 liveries need a test with this**
  (`REGPU_NO_RESOLVE_BANDS=1` turns bands off).
- **Skippable draws:** off-screen passes wait (stack). Blended plain rects may drop (stuken). Opaque rects and screen
  passes wait (main).

## Bugs the merge caused, fixed

- `pinfo.z` bit 17 was both stuken's point snap (on by default) and dwreckgg's min/max colour factor: every pixel
  shader multiplied colour by alpha. Min/max moved to bits 19-20 (`f973d03`).

The other bit fields (`tinfo.x`, pipeline key flags) were checked for collisions. Their layout:

- `tinfo.x`:
  - 0-1: sampler
  - 2-5: fixed16 components and copy
  - 6: fixed16
  - 7: plain
  - 8-13: exponent
  - 14-15: fixed16 mode
  - 16-17: border
  - 18-19: clamp
  - 20-22: anisotropy
  - 24-27: gamma
  - 28-31: mirror
- Pipeline key flags:
  - 0x100: strip cut
  - 0x200: coverage
  - 0x400: no-kill
  - 0x800: motion
  - 0x1000: fetch spec
- `pinfo.z`:
  - 2: kill skip
  - 3: 16_16
  - 5: 2-bit alpha
  - 6: alpha dither (offsets in 8-15)
  - 16: pixel position
  - 17: point snap
  - 19-20: min/max factors

## Skipped, and why

- **dwreckgg `up/ucode-past-end`:** the stack's `regpu-cf-jump-past-end` (PGR3) fixes the same bug, and FM3/PGR3 run on it.
- **stuken:**
  - **Duplicates of stack patches:** `a4aa21b` (column tiles: dwreckgg's version taken), `6520cd3` (`regpu-debug-shot-dump`),
    `e333d4d` (`regpu-memexport-log`), and `385e2a6` (texture rows, k_8 as R8 and the next heap made ahead, all in
    `regpu-texture-streaming` and `less-ram`).
  - **`ffb861f`** (k_2_10_10_10 front buffers in half float, dithered): it rewrites the grade and present path the stack
    changed (gamma into the back buffer, SSAA, triple screen, VR, 1010102 copies). Worth porting by hand later.
- **Tzeentchnet `bfbc2/stop-lifecycle`** (`regpu::Stop`, joining every thread): about 1,000 lines on an older base, across
  13 files. It needs redoing for the stack's threads (draw thread, replay, compile workers, texture helpers, VR, perf
  log). dwreckgg's `StopInterrupts` covers the use-after-free at shutdown.
- **FH1-ReImagined:**
  - `review/m7-recurring-rtv-fr02-wip`: a work-in-progress native-scene experiment.
  - `review/regpu-clip-motion-keys`: the same bug as the stack's `regpu-motion-flag`.
  - CODEOWNERS: specific to their repo.
- **Top Spin 4 `d0155f9`, `7541673`, `8280036`:** written against the early renderer and mostly diagnostics.
- **zer0ducksgiven/FM3-ReGPU `ccr-64e29f0e`** (patch 41 `regpu-replay-ring-writes`, off by default): it lives only on that
  experimental branch.

## Verified, and not

Both builds compile and link (D3D12, and with `REGPU_VULKAN`), and `tests/texture.cpp` passes. `regpu_vkprobe`
opens the device and compiles the shader preamble to SPIR-V (RX 7900 XTX). **Nothing has been run with a game.**
FM3 and PGR3 should be tested against `main` before their submodules move to it. Their stacks are now in `main`, so
their `tools/setup.ps1` must apply no ReGPU patches once they point at it.
